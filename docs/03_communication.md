# 03 溝通

## 規則

### 什麼時候發訊息

1. **只在三種情況發跨代理訊息（`send_message`，只送同一棵樹、會叫醒閒置子代理）**：gate 完成的一份 TASK REPORT、卡住需要決定、要對方立刻改變行動。總監發工單、裁決、回答對方的問題，也屬於第三種。
2. **不回 ACK**：不發「收到」「開始了」「做完一半」。收到指示就做，做完在檔案和 gate 報告裡交代。對方寫「不用回覆」就真的不回。
3. **一次完整**：指令、裁決、補充合併成一則；更正等下一則必要訊息一起帶，只有會造成錯誤動作的更正才立刻單獨發。
4. **狀態寫檔**：進度寫在自己的 `RESUME_STATE.md`、排程看板、工單進度。總監和總管定時讀檔。
5. **等別人做完**：有完成通知或 `wait_agent` 就用；沒有就請對方做完在 `RESUME_STATE.md` 寫好並用 `send_message` 回報，或總監自己讀檔。DSH 沒有 `notify_when_idle`；不要發「做完了嗎」、不要輪詢。
6. 同一件事要通知多人時，寫進共用檔案一次（規則檔或看板 `NOTICE`），不要逐一發訊息。
7. 訊息首行一句話說明是什麼；內容附檔案路徑，讓收件者自己讀檔，不要把長內容貼進訊息。

### PO 的訊息不漏讀

PO 的訊息有三個來源，總監每一個都讀，而且優先於 worker 訊息：
1. **待決帳與 `ask_user_question` 回覆**：每輪第一步（`docs/06`）唯讀讀 `DIRECTOR/PO_PENDING.md` 和對話裡還沒處理的回答，同輪執行或派工並關閉；未能完成則寫續辦紀錄。
2. **聊天裡的 PO 訊息**（包括工作中途插進來的）：同一輪先處理，再繼續原工作；同一輪登記進 `DECISION_REGISTER.md`；會改變做法的，同一輪寫進規則。
3. **PO 動作項**：PO 說「做好了」，就視同完成，立刻通知相關 worker。
- 每輪結束前自查：待決帳已讀、本輪 PO 訊息已處理並登記、已回覆項目已關閉或留有續辦紀錄。
- 處理晚了照實寫：幾點才讀到、晚了多久。
- 總監提出的待決項目如果已經不需要，主動撤回並寫原因，不讓舊題一直掛著。
- 有總管時，總管在例行檢查時查一次：已回覆超過 10 分鐘還沒關閉的，用 `send_message` 通知總監。

### PO 待決帳

- 要 PO 回覆、確認或動手的事，一律先記進 `DIRECTOR/PO_PENDING.md`，一筆一項，格式照 `templates/PO_PENDING.md`；能用 `ask_user_question` 問的就問（選項＋建議），答案原文貼回 `ANSWER`。聊天裡只說「待決帳新增了 OD-xx」，不能只寫在聊天裡。
- 要 PO 針對某條線回覆時，ACT 寫明哪條線和可照抄的句子。
- Worker 要 PO 的任何東西，先報總監（標題 `PO_REPLY_NEEDED`，附問題、選項、建議、影響、圖片路徑）；子代理不能問 PO（`ask_user_question` 回 `DELEGATED_CALLER`），硬問是違規。

### 回報給 PO

- 用 PO 指定的語言，先結論。只寫結論、要 PO 做的事、還沒驗證的事；細節放檔案。
- Worker 不把同一份內容再傳給 PO，除非總監要求。
- 時間戳一律讀系統時鐘（`date`），不估計。
